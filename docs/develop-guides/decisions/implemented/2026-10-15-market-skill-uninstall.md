# 市场技能安装与 Agent 配置

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/skills/market.py

## 问题

市场 Skill 安装后进入个人空间，却没有卸载入口。个人上传的原件可管理，而市场审核版本只可查看，用户无法撤销自己的市场安装。本人原件与历史市场安装折叠展示后，安装操作更难发现。

## 决策

市场发布版本继续保持只读。市场详情为已安装用户提供“在 Agent 中配置”和“卸载”；前者进入智能体管理，由用户针对具体 Agent 选择自动、固定或不启用 Skill，后者删除当前用户在 `market_skill_installs` 中的安装指针。个人空间折叠原件和历史市场安装时提供单独的“管理安装”入口。

卸载按稳定市场 slug 和当前用户身份执行，不以市场条目当前可见性或当前部门绑定为前提；重复卸载返回未安装，不删除发布版本、个人原件或其他人的安装。个人安装清单从本人已安装版本读取摘要，并标出当前是否可见；失去可见性后仅保留安装标识、版本和本人原件关联，隐藏描述、方向与他人的作者信息。个人空间仍保留卸载入口，但不开放该市场条目的详情或新版本。提交删除后刷新当前用户的沙盒 Skill 投影，运行时有效技能集合重新按当前安装记录和 Agent 配置计算。固定选用已卸载 slug 的 Agent 需要重新选择 Skill。

## 替代方案

- 把市场安装纳入个人 Skill 的文件删除：会误删作者原件或审核发布目录，且与市场安装指针的所有权不符。
- 允许编辑市场审核版本：会让运行内容脱离审核快照，也不能解决用户撤销安装的需求。
- 卸载时自动修改所有 Agent 配置：会改变用户明确保存的选择，且跨越安装与 Agent 配置的所有权边界。

## 后果

卸载立即移除当前用户的市场版本投影；已开始但尚未读取该 Skill 文件的 Agent Run 可能因此读取失败。新 Run 不再获得已卸载市场版。若投影刷新在数据库提交后失败，接口报错，重试相同卸载会再次刷新投影并返回未安装。市场条目范围后来收窄时，卸载接口仍接受原安装用户请求，避免残留无法清理的安装指针。

## 验证

真实 HTTP/PostgreSQL 隔离 Schema 与同源技能集成测试 2 项通过，覆盖本人和他人安装、部门变化后仅返回本人已安装版本摘要、重复卸载、发布版本保留、用户投影移除及默认与固定 Agent 的有效集合。后端相关单测 41 项、前端目录和 @候选单测 9 项通过；Ruff、前端 ESLint、Vite 构建和 `git diff --check` 通过。

完整后端非慢速单测在既有知识库等模块出现失败，并在后续测试中无进展后中止；工程契约检查仅报告其他两份既有决策记录的 4 个错误。文档构建所需依赖未安装，构建未完成。浏览器自动操作被安全策略禁止，页面交互仍需在预览中人工检查。
