# 技能页按全局、部门和个人范围展示

状态：implemented
类型：feature
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

技能页将内置、共享和个人 Skill 混合展示，超级管理员无法按部门、人员查看个人 Skill。共享卡片的适用范围也不够明确。

## 决策

内置 Skill 标为全局；共享 Skill 展示真实授权范围，其中部门共享展示部门名称。管理员通过专用接口分页查看权限范围内有效用户的个人 Skill，可按部门和用户名或账号筛选；部门管理员只能查看所属部门，超级管理员可以跨部门。该接口及跨用户文件预览均在后端校验管理员身份和部门范围；普通用户继续只管理自己的个人 Skill。页面分类和筛选不改变 Skill 的运行权限，也不将历史全局或指定人员共享误标为部门共享。管理员直接发布边界见[部门个人 Skill 查询与管理员直接发布](./2026-10-10-department-personal-skill-publishing.md)。

## 替代方案

- 让普通 `/api/skills` 直接返回全员个人 Skill：会扩大普通用户的数据可见面，也缺少分页。
- 先统一迁移所有共享 Skill 为部门权限：改变现有授权与运行行为，超出本次页面改造范围。

## 后果

个人 Skill 存在文件系统中，按用户分页会出现某页用户没有 Skill 的情况；页面仍提供继续加载入口。跨用户预览复用现有受控文件读取边界，不开放跨用户编辑或导出。

## 验证

- `test_personal_skill_catalog_router.py` 通过内存 ASGI HTTP 验证部门管理员范围、超级管理员筛选与分页、目标用户文件读取，以及普通用户、跨部门和已删除用户拒绝。
- 前端 ESLint、Vite 构建、Skill 目录现有单测通过；使用模拟数据在真实浏览器中检查桌面和 390px 窄屏页面、部门与人员筛选、其他用户只读预览。
- 工程信任检查仍因两份既有决策记录的元数据错误未通过；本决策记录通过其格式检查。
