# 数据总览的历史使用与当前资源口径

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/repositories/dashboard_repository.py

## 问题

管理员需要审计已经发生的使用。统计查询按会话、用户和智能体当前状态过滤历史，删除会使过去的消息、工具调用和用量减少。会话更新时间无法表示同一会话中的多次执行，图表和明细不同的筛选口径妨碍核对。

## 决策

DashboardRepository 从保留的 PostgreSQL 记录读取历史使用，不根据会话删除、项目删除、用户注销或智能体移除过滤历史。系统概览分别展示历史累计会话、消息、反馈与当前可用项目、会话、用户。当前项目仅包含 selectable Project，当前会话包含可用智能体、未注销用户及有效项目下的未归档和已归档普通会话。权限继续由超级管理员依赖控制。

会话分析与列表共享周期、用户、智能体、项目、状态、关键词及子会话筛选。Web 默认全部历史和全部状态；指定周期时，纳入该周期新建或产生消息、Run 的会话，消息按实际持久化条数统计，排除内部 Model/Tool 审计消息；Run 用量归入执行开始时间，历史缺少开始时间时使用创建时间。仅在全部历史范围保留无 Run 会话的旧非零用量汇总，无法确定日期的旧汇总不分摊到指定周期。未开始的 pending 和 cancelled Run 不计入 Token 用量或缺失执行数。已删除子会话通过持久 SubagentThread 关系识别。项目归属显示名称、删除状态及无项目会话标记。

列表与分析共享同一筛选语义；详情始终展示完整会话。全部历史模式的增长趋势明确展示近 30 天，分布与列表展示全部保留历史。分页使用已提交关键词，迟到响应不能覆盖新筛选，失败清除旧结果并允许重试。

智能体调用按 AgentRun.started_at 计已开始执行，模型调用按持久 Model 消息及其实际开始时间计已记录调用，包括中间审计消息。工具统计只计 success/error，按 ToolMessage 中 compatibility_tool_call_id 关联真实开始时间；该绑定支持审批后跨 Run 恢复，缺少 lifecycle 的历史记录使用 ToolCall 创建时间。Token 趋势读取 Run 聚合实测用量，并显示不完整执行数；各时间桶按上海日历边界和 ISO 周年生成，总计等于所选周期各桶之和。

## 替代方案

只增加“包含已删除”开关仍会让默认使用量缺失，也无法解决执行次数和时间归属。独立审计仓库引入迁移和双写责任；保留的业务事实可以满足当前范围。直接使用最终 assistant 消息的 Token 会漏掉同一次执行中的其他模型调用，因此采用 Run 聚合并明确按执行开始时间归属。

## 后果

查询与页面展示改变，删除行为、文件、持久化 schema 和权限保持原语义。不提供归档或操作审计日志。物理清除或从未采集的事实不能补回，模型调用和 Token 仅代表已记录使用，不能作为完整外部账单。Token 完整性与展示沿用[会话用量决策](./2026-09-12-dashboard-stat-corrections.md)，其累计查询范围及分期规则由本记录补充。
