# 统一技能入口

状态：implemented
类型：simplification
Owner：web/src/components/extensions/SkillMarket.vue

## 问题

“技能”和“Skill 市场”曾分列扩展页的顶层标签。内置、共享、个人和审核发布的技能都在帮助用户选择 Agent 能力，但分散入口使同一技能可能重复展示，也使个人管理与审批难以发现。

## 决策

扩展页只保留“技能”标签。主区域展示当前用户可见的市场、共享和内置技能，右侧个人空间展示个人源技能、已安装市场技能和发布申请。市场与旧共享条目使用相同 slug 时，公共目录展示市场版本；个人源技能只在个人空间展示。原有技能管理组件在页内抽屉中继续提供编辑、上传与共享功能。旧 `tab=market` 链接转到统一入口。

市场审核、安装和点赞继续通过现有 API 与后端权限实现。同一个人原件经共享和市场分别发布后的来源合并规则见[同源技能合并展示](./2026-10-15-skill-origin-dedup.md)。部署使用原项目数据目录；市场表由现有迁移流程补建，不复制或重写原有技能与账号数据。

作者从市场卡片查看自己的个人原件时，详情链接携带个人范围；共享和内置技能继续进入公共详情范围。详情页按范围查找同名技能。

## 替代方案

- 只改两个标签的名称：目录重复与操作分散仍在。
- 把旧共享技能迁入市场：会改变自动可用、审核和版本语义。
- 重写旧技能管理组件：会扩大改动范围并增加既有上传、共享功能的回归风险。

## 后果

用户从一个入口发现和管理技能。旧共享/内置技能仍遵循原权限和可用性规则，市场技能仍需安装；相同 slug 的公共卡片以市场发布版本为准。个人空间的市场安装列表独立获取，避免只显示公共目录首屏已安装项；同一来源的作者个人原件和本人市场安装合并展示。停用的旧技能不作为可用卡片展示。原有数据目录在部署前完成停机备份。

## 验证

- 前端合并与隔离逻辑单测通过；涉及组件的 ESLint 和生产构建通过。
- 市场卡片指向原始个人 Skill 卡时，组件交互测试点击“查看个人技能”并验证进入个人详情范围；路由单测覆盖普通共享卡继续进入公共范围。
- 原服务 `/api/system/ready` 返回 ready，首页返回 200；原数据库账号仍为 9 个，市场表已建立。
- 后端完整 unit gate 补齐容器测试挂载后已执行；到 81% 时有 1874 项通过、12 项失败、53 项跳过，随后技能服务用例长时间无进展而中止。失败项位于评估、知识库、子 Agent 和系统路由测试；此次界面整合未修改后端模块。
- 工程契约检查仍有其他历史决策记录的元数据问题；本记录符合当前格式。
