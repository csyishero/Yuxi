# 会话移入已有项目并逐文件导入

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/conversation_service.py

## 问题

独立会话可以原地转成新项目，但无法进入已有项目并在后续运行中使用目标目录。源目录可能由其他会话共用；整目录复制会把其他会话的文件带入目标项目。

## 决策

会话菜单提供“移入已有项目”。所有者选择自己的有效项目，逐个勾选或全选当前已打开文件夹中要复制的普通文件；子文件夹需要进入后选择，默认不导入任何文件。用户可以逐项跳过重名文件，或为导入文件改名。已有目标文件绝不覆盖，未选文件及全部源文件保留在原目录。单次导入最多 100 个文件、单文件 50 MB、合计 100 MB。

服务通过用户目录锁、源与目标项目锁以及根/持久子会话锁验证所有权与状态。存在运行、排队、待清理或待回复中断时拒绝迁移。请求必须带幂等 ID；相同目标和文件意图的重试返回已经提交的结果。文件复制成功后，数据库事务将根会话及持久子会话一起改绑目标项目，保留 thread ID、消息、Run 与 checkpoint，并记录源项目、原目录及导入结果。后续运行根据当前项目绑定使用目标目录。

历史附件删除按持久化源目录记录授权，仍被有效迁移会话引用的原目录不能清理。个人空间继续展示这类隐式项目原目录，使未导入的旧文件仍可找到；该原项目不成为可选择的迁移目标。原始会话创建请求继续按原创建意图幂等重放。[独立会话原地转为新项目](2026-10-09-promote-conversation-project.md)保持其原目录不变的语义。

## 替代方案

- 只调整侧栏分组：后续 Run 仍绑定原工作目录。
- 自动复制整个原目录：会带入同目录下其他会话的文件。
- 搬走或删除原目录：历史附件、消息及 checkpoint 中的绝对路径可能失效。
- 创建新会话并导入文件：原线程的历史和继续对话入口会断开。

## 后果

文件系统与 PostgreSQL 没有共同事务。已知的复制或提交失败会清理本次新建且仍可确认身份的目标文件；进程在复制后、数据库提交前突然退出，可能留下目标目录中的孤立文件，重试时作为同名冲突交给用户处理。原目录和未选文件不自动删除；历史文本中的相对路径在后续运行中按目标目录解释。
