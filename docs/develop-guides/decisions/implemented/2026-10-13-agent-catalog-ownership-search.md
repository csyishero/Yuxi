# 智能体目录展示创建人和部门

状态：implemented
类型：feature
Owner：backend/package/yuxi/repositories/agent_repository.py

## 问题

智能体列表仅展示名称、标识和共享范围。多个部门或人员创建同名智能体时，用户无法从卡片辨认创建人；原有搜索也无法按姓名、账号或部门查找。共享范围原先只写“读部门(2)”之类的数量摘要，用户无法知道具体共享给哪些部门，还容易把创建人部门误认为共享目标。

## 决策

智能体列表先按原有权限取得当前用户可见的智能体，再批量查询这些智能体创建人的用户名与当前部门，并在响应中提供归属标签。系统预置智能体通过独立的 `owner_is_system` 字段标识，避免与名为“系统”的真实创建人混淆。可见性与编辑、删除权限仍由智能体 repository 决定；归属标签不授予额外权限。

智能体页面沿用 Skill 页的分组卡片、共享范围标签、搜索栏和窄屏布局。主智能体与子智能体先分成两个区域，各自再按共享范围分组；系统预置智能体归入各自类型的系统预置组，读取范围只包含创建人的智能体归入个人组。子智能体不展示普通对话入口。卡片展示创建人与部门；通用关键词匹配名称、标识、描述、创建人和部门。管理员另可按创建人所在部门及姓名或账号筛选。部门下拉框读取完整部门目录，即使某部门当前没有可见智能体也仍可选择；筛选结果始终限于已加载的可见智能体。页面行为由 `web/src/components/model-management/AgentManagePanel.vue` 负责。

列表接口为可见智能体批量解析读取、编辑和管理范围中的部门名称，并按配置中的部门顺序返回。卡片把每个已设置的权限范围分别标明，并列出具体部门；创建人的当前部门明确标成“创建人部门”。缺失的部门保留“已删除部门 #ID”线索。普通用户不能调用管理员部门目录，因此由智能体接口提供这些展示名称；名称只用于说明已有权限，不改变共享范围或授权判断。关键词也匹配卡片上显示的共享部门名称。

## 替代方案

- 前端另查用户与部门目录再拼接标签：会增加请求和权限分支，普通用户也不能依赖管理员目录接口。
- 继续只显示共享部门数量：卡片很短，但无法判断究竟是哪两个部门，正是本次发现的问题。
- 新增跨用户的服务端智能体目录与分页搜索：当前列表已一次返回可见智能体；为这次展示增加目录接口会扩大查询和授权表面。
- 继续只显示共享范围：共享对象与创建人是不同信息，不能解决同名智能体的辨认问题。

## 后果

查看者会看到其有权访问的智能体的创建人姓名及当前部门。部门是创建人查询时的所属部门，人员调动后卡片随之变化，不表示创建时部门或资源的独立归属。创建人资料无法查询时，界面保留已有创建人标识并显示未知部门。

共享范围中的部门名称是当前部门目录的名称，与创建人部门分开显示。部门改名后名称随查询结果变化；已删除的部门仍以 ID 占位，避免把无效范围误读成另一个部门。范围较多时卡片标签换行显示，不隐藏具体部门。

部门与创建人筛选只作用于当前用户可见、已加载的智能体；它不是全体人员或全体智能体检索。“创建人部门”与卡片的共享目标部门是两种不同含义。完整部门目录可以包含没有匹配智能体的部门，选中后展示空结果；刷新目录时若已选部门被删除则清除筛选。权限边界保持在后端，卡片上的编辑和删除入口继续按各自授权显示。
