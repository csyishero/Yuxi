# 知识库目录上传实体化与虚拟目录按需删除

状态：implemented
类型：feature
Owner：backend/package/yuxi/repositories/knowledge_file_repository.py

## 问题

带相对路径上传的文件若仅把路径保存在 `filename`，列表会投影出没有持久 ID 的虚拟文件夹，用户无法对其执行真实文件夹的编辑和删除操作。历史数据中也存在这样的记录。

## 决策

新上传文件的 `source_path` 在接收请求时校验相对路径和重复路径。写入文件元数据时，在同一 PostgreSQL 事务中按目录段复用或创建真实文件夹，并将文件写在末级目录下。创建的文件夹记录保存操作者和服务端时间；同一知识库的新目录上传与历史迁移使用目录树 advisory lock 串行化。遇到同名普通文件、重复目录或尚未整理的同名历史路径时，当前文件写入失败，事务回滚。

历史虚拟目录保持原有投影，知识库详情不启动转换任务。用户在文件列表确认删除虚拟目录时，前端把真实父目录 ID 和虚拟路径前缀交给删除接口；后端以知识库和父目录限定查询范围，在目录树锁内逐批删除该虚拟目录中的文件、原始与解析对象以及导图引用，并刷新统计。失败时保留尚未删除的记录，用户可再次删除。前端操作由 `web/src/components/FileTable.vue` 拥有；删除范围由 `KnowledgeFileRepository` 校验，文件副作用由知识库 executor 和对象存储辅助函数执行。

## 替代方案

- 保留新上传的虚拟目录：会继续产生不可用真实文件夹功能的新数据。
- 在列表读取时写入历史目录：读取会产生持久副作用，分页和并发读取难以限定写入范围。
- 删除前先持久化将立即删除的虚拟目录：会产生额外目录写入和冲突处理，删除结果不需要该中间状态。

## 后果

新上传文件拥有真实目录链，可用现有文件夹操作。历史虚拟目录只在用户确认删除时按所选前缀处理；未删除的历史目录保持原样，原有知识库级转换 API 仍可由管理者按需使用。删除中的部分失败保留剩余文件供重试，不自动改名；包含类型不明记录的路径会被拒绝，避免扩大不可逆删除范围。目录名称的数据库级唯一约束仍由[同级名称约束提案](../proposed/2026-08-24-knowledge-folder-materialization.md)跟踪。
