# 独立对话原地转为项目

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/project_service.py

## 问题

历史对话选目录创建 linked Project 的旧入口被专属 managed 目录方案移除。用户需要把已有独立对话组织为可见项目，同时保留文件、链接、消息与执行归属。

## 决策

历史对话菜单提供“转为项目”，填写名称并展示原目录。服务按用户目录锁 → Project 锁 → Conversation 锁验证归属及存活状态，将独立 implicit managed Project 原地改为 selectable 并设置名称。Project ID、Conversation.project_id、Workdir 路径、消息、Run 和文件字节不改变；不创建、复制、移动或重命名目录。相同对话的重复请求返回已经可见的项目，不重复创建或覆盖名称。原始无项目创建请求通过 Project 的 thread:<request_id> 持久标识维持幂等性，提升可见性不改变创建意图。

只允许具有自身 ID 标识的 managed 子目录、独占普通对话且无其他共享绑定的项目转换。历史 linked、容器根、无效或缺失目录、共享普通会话、已删除记录拒绝。项目自己的子会话保持原归属；不把子会话作为转换入口。有效 managed 子目录不因历史严格上层关联自动失去归属，沿用现有 overlap 与工作准入规则。目标项目的运行、排队或待清理任务不阻止原地转换；重叠上层的其他任务仍遵守现有目录准入检查。取消与请求失败保持原状态。

转换成功更新项目列表和所有已加载同项目会话的删除能力，展开项目并定位原会话。已有可见项目提供“打开所属项目”。删除项目中的单个会话不能清理项目目录；项目删除沿用默认保留、显式勾选才清理的规则。旧共用目录的文件迁移不在范围内。

## 替代方案

新建记录并移动会话需要改变不可变 project_id，复制目录还会造成历史路径与新文件分叉。原地提升隐藏 Project 能保持同一所有权。可见名称与磁盘日期目录名称可以不同；这与项目重命名不移动目录一致。无持久化 schema 变更。
