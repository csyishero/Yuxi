# 我的技能来源精确总数

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/skill_catalog_summary_service.py

## 问题

“我的技能”的“全部”和“我创建的”标签需要表示完整结果数量。个人技能由 UserWorkspace 文件目录持有，分页接口只读取当前页及下一项；页面已加载卡片数不是完整数量。“全部”还折叠个人原件与本人市场安装、同源共享版本和被安装市场版本覆盖的共享卡片，不能直接相加来源数量。

## 决策

个人分页接口继续有限扫描，由[技能列表分页方式](./2026-10-19-skill-list-pagination.md)记录其页码语义。已登录用户通过独立的 `/api/skills/summary?search=` 请求取得 `created_total` 与 `all_total`，列表请求不等待该统计。统计读取本人全部有效个人技能、当前可见的共享及系统技能和本人安装事实，沿用现有授权与安装搜索条件，再按个人空间的同源折叠规则计算“全部”。搜索条件同时作用于两个总数；隐藏市场安装只允许公开 slug 参与搜索，其不可见详情不进入统计条件。

“全部”中的共享及系统卡片使用 `/api/skills?source=shared&catalog_all=true`，分别传 `shared_kind=shared` 和 `shared_kind=builtin`；本人市场安装使用 `/api/skill-market/-/installs?catalog_all=true`。服务端先按当前用户的完整来源身份折叠，再分页和返回该来源在“全部”中的总数。普通“团队共享”“系统内置”“市场已安装”来源仍使用原始分页，供用户查看各版本及安装记录。这样即使对应的个人原件、市场安装或另一共享版本位于后页，“全部”的行数、翻页和总数仍采用同一组逻辑身份。

## 替代方案

- 显示当前页或已加载数量：读取快，但标签数字会随翻页变化，不能表达完整结果。
- 在每次个人技能翻页请求中计算总数：接口较少，但每次翻页都扫描完整文件目录。
- 给个人技能增加数据库索引：查询更快，但需要迁移并维持 Agent 文件写入与索引的同步。

## 后果

统计请求完整扫描当前用户的个人技能目录，并读取授权共享卡和本人安装身份；耗时随目录及关联记录规模增加。统计与分页相互独立，个人技能翻页继续只解析到当前页和下一项；“全部”的共享、系统和安装分页会额外检查本人的安装及同名个人原件身份。总数表示一次请求时的授权结果；并发发布、安装或删除可能使随后加载的页面数量变化。没有新增数据库字段或迁移。
