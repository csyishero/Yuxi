# 对话仍有任务时允许原地转为项目

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/services/project_service.py

## 问题

对话转项目只更新隐藏 Project 的名称与可见性，却复用了“删除目录前必须无运行、排队和清理任务”的检查。用户正在对话或任务刚结束时会收到任务占用错误。项目 ID、会话归属和文件路径均未改变；该检查不保护转换中的任何文件操作。

## 决策

保留用户目录锁、Project 锁、Conversation 锁、managed 目录归属与重叠绑定检查。原地提升时允许目标项目有正在运行、排队或 runtime 清理中的任务。目录验证仍只打开现有路径，不创建、不移动、不删除文件。删除项目文件时继续执行现有活动任务检查，避免误删运行时文件。项目转换的服务是此限制的 Owner，前端仅维护业务错误的展示清单。

## 替代方案

继续等待任务结束会让长任务或中断清理阻止纯元数据转换；转到新目录会改变持久文件路径。当前生命周期已稳定以 Project ID 和 Workdir 路径授权，转换不改变它们。

## 后果

转换期间运行任务可继续写原目录，项目 ID 与 Workdir 路径不变。项目文件夹删除仍要等运行、排队及清理任务结束。若目录存在其他项目共享绑定，仍按现有重叠检查拒绝转换。

## 验证

- 相关后端 unit 58 项通过，覆盖 running、queued、cleanup_pending 转换与项目文件夹删除拒绝；原目录文件字节、ID 与路径不变；linked、错误目录 ID、共用目录继续拒绝。
- 真实 HTTP + 独立 PostgreSQL 通过：活动 Run 期间转换返回 200，Run 的状态及会话归属不变，文件字节保留；选择删除项目文件夹返回 409。原有并发等待、权限与项目已删除时不复活的检查同时通过。
- 真实浏览器页面受此前自动审批限制，视觉未验证。
