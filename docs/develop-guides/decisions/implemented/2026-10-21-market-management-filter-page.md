# 市场上架管理清单的筛选与分页

状态：implemented
类型：feature
Owner：backend/package/yuxi/agents/skills/market_repository.py

## 问题

市场上架管理需要按名称、状态和范围定位条目，同时保留已下架记录和部门管理员的权限边界。一次读取所有可管理条目使查询量随市场增长，左侧滚动也难以定位目标。

## 决策

管理仓储在同一授权条件下筛选并分别计算总数和读取当前页。搜索匹配最新审核版本的名称或稳定 slug，不匹配历史版本；状态区分已上架和已下架，范围区分全公司和部门。部门管理员始终只能读取当前属于本部门市场的条目，超级管理员可以读取全部。列表按更新时间降序和 ID 稳定排序，默认每页 20 条，接口返回 `data`、`total`、`offset`、`limit` 与 `has_more`。

管理抽屉提供搜索、状态筛选、总数和分页；范围筛选仅向超级管理员展示。从市场详情进入管理时，以精确 slug 定位目标，手动搜索或改变筛选后恢复普通搜索。筛选和翻页清除旧详情，迟到响应不能覆盖新条件；非首页出现空数据时回第一页重查。单条管理详情仍由后端独立校验当前权限。公开技能市场沿用自己的搜索与分页接口。

## 替代方案

- 前端一次加载全部再筛选和分页仍使查询无界，数据变化后列表与总数易过期。
- 单独建设管理搜索服务会复制已有的管理授权和条目投影。
- 仅按总数计算有效页无法处理管理员并发修改发生在计数与取页之间的短暂空页。

## 后果

列表读取有界，每次请求增加一条计数查询。偏移量分页不保证跨请求快照一致；条目变化可能移动页边界，页面以重新查询后的数据库结果为准。管理接口的搜索词上限为 128 字符，与有效 Skill slug 长度一致。精确 slug 定位仍受同一管理员权限条件限制。

## 验证

- 真实 HTTP/PostgreSQL 市场集成测试在新增长 slug 边界前 65/65 通过；随后 128 字符合法 slug 和 129 字符非法搜索词的聚焦用例 9/9 通过。测试覆盖部门越权、已下架筛选、范围、总数与多页排序。
- 前端完整单元测试在最终前端代码上通过，针对管理筛选、分页、直达定位、迟到响应和空页回退的聚焦测试 48/48 通过；ESLint 与后端改动文件 Ruff 检查通过，Web 生产构建通过。
- 已重启现有本机 API 容器，健康检查通过；运行中的 Web 容器已读取新构建资源。
- 浏览器真实页面检查未执行：浏览器工具的管理策略校验不可用，访问本机页面被拒绝。后端全量非 slow 单元测试另有 12 项位于未修改模块的失败。工程信任检查另有 4 项既有决策记录元数据错误；上述失败不作为本功能通过的证据。
