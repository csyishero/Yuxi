# Skill 共享申请原因

状态：implemented
类型：feature
Owner：backend/package/yuxi/agents/skills/sharing.py

## 问题

个人 Skill 的共享申请拥有待审、批准、驳回和文件快照，但申请人缺少解释共享用途的字段。审核意见由管理员填写，与申请人的理由属于不同信息，不能共用。

## 决策

申请人提交共享申请时填写最多 1000 字的原因。共享服务去除首尾空白并拒绝空白或超长原因，将原因与提交时的不可变文件快照、申请人、时间和审核状态一起保存。管理员在现有共享申请列表中查看原因和快照，按既有部门范围批准或驳回；申请人查看自己的处理结果。管理员直接发布个人 Skill 时记录系统原因“管理员直接发布”。

PostgreSQL 模型与显式 Schema v9→v10 迁移拥有持久字段；共享服务拥有提交校验和审核流程；HTTP 路由装配请求与响应；前端展示输入、申请原因和审核记录。历史申请的原因保持空值，界面说明该记录未填写原因。

## 替代方案

- 把申请原因写入审核意见：申请与审核信息会互相覆盖，历史记录难以解释。
- 新增独立工单表与状态机：现有申请记录已经拥有状态、快照和审核人，重复建模增加维护成本。
- 仅在前端增加自由文本：刷新后无法供管理员稳定查看，也无法审计。

## 后果

新申请必须填写原因才能进入待审队列；已有待审和历史申请保持原状态与快照。管理员可以同时核对申请理由和提交时文件。Schema 升级完成前，使用 v10 模型的 API 和 worker 不接收流量。

## 验证

- 单元测试覆盖空白和超长原因、独立存储、管理员直接发布及部门范围；真实 PostgreSQL 测试覆盖历史行保留空原因及迁移幂等。
- 隔离数据库 HTTP 测试覆盖申请、列表、快照和审核生命周期；前端 API 测试覆盖原因随请求发送。
- 前端 lint、生产构建和真实页面检查覆盖申请输入与管理员待审列表。
