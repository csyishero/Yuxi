# 普通用户查看部门共享 Skill 名称

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

技能页通过仅管理员可用的部门列表接口把共享范围的部门 ID 映射成名称。普通用户无法调用该接口，因此部门共享卡片退化为“部门 #ID”。

## 决策

技能卡片列表在后端仅为当前用户可见的部门共享 Skill 附带共享部门名称，名称顺序与授权范围中的部门 ID 一致。前端优先显示卡片携带的名称。管理员的完整部门列表接口用于管理筛选和审核。可见性由 `skills/service.py` 判断，部门名称由 `DepartmentRepository` 查询，卡片标签由 `SkillCardList.vue` 渲染。

## 替代方案

- 将完整部门列表接口开放给所有用户：会扩大无关部门数据的可见面。
- 只用当前用户的部门名称：无法正确显示跨多个部门共享的 Skill。
- 显示固定“部门共享”：丢失卡片现有的准确范围信息。

## 后果

接口只增加当前可见卡片的 `read_department_names` 字段，不开放完整部门列表给普通用户。历史共享范围指向已删除部门时显示“已删除部门 #ID”，避免伪造仍存在的部门名称。

## 验证

- 内存 ASGI HTTP 用普通账号验证多部门共享返回“科技部门、测试部门”，不可见 Skill 的部门名称不出现在响应中。
- 前端 ESLint、Vite build、现有技能目录单测通过。
- 本地 Yuxi 更新后，部门共享卡片实际显示部门名称，API readiness 返回 200。
