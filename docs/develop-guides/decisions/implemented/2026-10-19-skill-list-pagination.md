# 技能列表分页方式

状态：implemented
类型：feature
Owner：web/src/components/extensions/SkillMarket.vue

## 问题

技能市场、我的技能和技能治理虽然按批次请求数据，页面仍只提供“加载更多”。用户无法直接跳页，也无法辨别数据库列表的准确总量。个人技能存于文件目录，当前分页只解析到本页之后的一个有效技能；为了总页数而在每次请求扫描所有人的技能会抵消已有性能优化。“我的技能·全部”还会跨来源折叠同一技能，不能相加各来源总数。

## 决策

- 数据库列表继续在授权和筛选后排序、计数、分页。市场目录返回准确 `total`，保留现有 `data` 数组及 `offset/limit` 接口。我的市场安装和治理共享技能复用现有总数。
- 页面上的列表由“追加数据”改为“替换当前页”。市场默认每页 24 项，已安装、共享与系统技能默认每页 30 项，显示准确总页数并允许选择每页数量。治理共享技能默认每页 30 项；其他成员个人技能独立翻页，不把展示分组误当独立查询。
- 我的技能来源保持现有分类；“全部”展示各来源的独立页，避免伪造跨来源总页数。共享和内置来源在授权查询中排除已停用及退役项，来源页逐项展示实际计数的技能；“全部”继续折叠同源共享版本。个人文件源仍只读取当前页和下一项，显示当前页及前后页；数据库源显示准确总量和可跳转页码。
- 个人原件和作者自己的市场安装即使不在同一页，也通过当前页限定的同源关联信息合并为一个管理入口。市场卡片上的共享可用状态由后端按当前市场页及权限判定，不依赖共享列表恰好加载到同一页。
- 搜索、部门、人员、方向或来源变化时回到第一页；旧请求不能覆盖新筛选结果。页末记录被删除时回退到仍有内容的最后一页。

## 替代方案

- 把全部来源一次读入浏览器再切页：实现简单，但传输和加载量随数据增长，不解决原问题。
- 为个人文件技能增加数据库索引：可提供快速精确总页数，但需要迁移和可靠的文件／数据库同步，超过本次界面改造范围。
- 每次完整扫描文件目录取得精确总数：不新增 Schema，但数据量大时所有分页请求都会变慢。

## 后果

市场、共享和安装列表每次翻页会执行授权后的总数查询；个人技能保持文件目录事实来源，分页接口不计算精确总数。个人空间标签的独立精确计数由[我的技能来源精确总数](./2026-10-20-skill-personal-space-counts.md)记录。跨页关联只查询本人的当前页条目，不为了合并界面扫描全部技能或加载全部安装。旧版无 `limit` 的接口响应保持兼容；没有新增数据库字段或迁移。

个人文件目录的分页接口不提供快速精确总页数；用户只看到当前页与前后页。并发发布、安装或删除会改变列表长度，客户端对空白尾页作回退。接口总数仅代表本次授权查询时的快照，不承诺跨请求不变。组件测试的完整串行运行曾因本机 Vite 测试运行器的模块请求超时而中断；分页的定向断言和生产构建通过。

隔离 schema 的 PostgreSQL 集成测试未完成：测试在建 schema 前连接现有 PostgreSQL 时返回 `the database system is in recovery mode`，没有读取或修改现有业务表。相关授权与分页场景已由 SQLite ASGI HTTP 测试验证；恢复 PostgreSQL 后应重跑 `test_skill_market_http_postgres.py`。
