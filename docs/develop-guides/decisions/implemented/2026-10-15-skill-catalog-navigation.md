# 技能目录按方向浏览，来源作为筛选条件

状态：implemented
类型：simplification
Owner：web/src/components/extensions/SkillMarket.vue

## 问题

主目录把“全部、市场、共享、系统、已安装”并列成一级导航。其中市场、共享、系统是发布来源，已安装是当前用户的使用状态；右侧个人空间也提供本人安装清单。混在同一级后，用户需要先理解来源和状态的区别，且“已安装”与个人空间重复。

## 决策

主区展示统一技能目录，搜索和技能方向仍直接可见；市场发布、团队共享、系统内置放进标注“来源”的次级选择框。市场热门榜保持独立入口，并明确它只统计市场发布的技能。本人市场安装通过右侧“我的技能”和管理抽屉查看、配置或卸载，不占主目录一级位置。目录组合和权限仍由现有 API、来源关联及服务端授权决定。

## 替代方案

- 维持原一级标签并把“已安装”改名：来源与状态混列的问题仍存在。
- 增加“发现／我的”两套一级页面：会与右侧个人空间形成新的重复导航。

## 后果

来源筛选仍可使用，但不再决定页面的主结构。已安装用户从个人空间进入管理；主目录保留最新发布的可见市场条目和共享/系统条目。来源筛选为空时应提示切换来源，不暗示整个目录为空。

## 验证

- 旧能力不存在：主区不再显示“市场／共享／系统／已安装”并列一级标签，`已安装` 不再触发独立市场分页查询。
- 重新引入条件：如未来出现与技能目录不同的独立安装管理流程，应根据任务差异重新设计导航，不直接恢复混合标签。
- 技能目录组合、来源过滤和个人安装的相关单测通过；完整 ESLint 与 Vite 构建通过。浏览器自动操作受本机安全策略限制，最终页面外观仍需在预览中人工核对。
