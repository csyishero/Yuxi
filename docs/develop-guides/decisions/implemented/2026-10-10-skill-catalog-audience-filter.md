# 技能目录按人员筛选共享范围

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

管理员在技能页输入人员姓名或账号时，原有筛选只查询个人 Skill。共享区仍列出所有可见 Skill，容易把“该人员可用”与“管理员可见”混淆。

## 决策

人员条件同时用于个人 Skill 目录和共享卡片列表。共享卡片在原有管理员可见性约束后，再按命中用户的 UID 或部门判断读取范围：指定人员共享匹配 UID，部门共享匹配部门，全局共享适用于任一命中用户。内置 Skill 属于全局能力，始终保留。部门管理员的目标用户限本部门；查询只返回有效用户。前端仅在提交搜索时应用条件，避免输入过程中刷新其他操作导致筛选不一致。

## 替代方案

- 仅在前端按共享卡片的用户名标签过滤：无法准确覆盖部门共享，也无法识别没有个人 Skill 的目标用户。
- 使用现有人员选择器的前 1000 个用户在浏览器筛选：超过上限会遗漏人员，不适合作为目录查询依据。

## 后果

搜索词若匹配多名用户，共享区展示他们可用 Skill 的合集；没有匹配用户时，共享区为空，全局内置项仍显示。筛选仅影响目录呈现，不改变任何 Skill 的读取权限或运行范围。

## 验证

- HTTP 回归用例覆盖部门共享、指定人员共享、全局共享、无匹配用户及普通用户越权查询。
- 前端 lint、构建和技能目录相关单测通过；完整前端单测在当前沙盒中因 Vite WebSocket 监听被拒而无法完成。本地服务更新后验证接口及页面可访问。
