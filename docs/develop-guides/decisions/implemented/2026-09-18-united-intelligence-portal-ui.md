# 联合智擎门户视觉接入 Yuxi

状态：implemented
类型：feature
Owner：web/src/views/HomeView.vue

## 问题

UI 交付的“联合智擎”原型包含开屏、账号登录、全局侧栏、新建对话和智能体管理五类界面，但原型使用静态 HTML、内嵌图片和模拟交互，不能直接替代 Yuxi 的真实鉴权、路由、对话和管理功能。需要在不改变现有业务契约的前提下，将品牌视觉和信息层级接入现有 Vue 页面。

## 决策

- 将 UI 提供的开屏背景和组合 Logo 作为前端静态品牌资源，由 `HomeView` 按原始宽高比展示，并用真实按钮承接登录或进入对话的路由。
- `LoginView` 保留首次初始化、账号密码、锁定倒计时、用户协议、OIDC、健康检查和错误反馈，仅重组为原型的“品牌说明 + 登录卡片”布局。
- `AppLayout` 继续拥有真实导航、对话历史、项目、搜索、任务中心和用户入口，只替换展开态品牌标识，并统一侧栏的背景与选中态。
- 新建对话继续使用现有 Agent、附件、模型、工具审批和消息发送组件，仅调整标题、输入区和背景装饰；智能体管理继续使用真实数据与既有管理组件。
- 新增门户品牌 CSS token，并为暗色模式提供对应值。不引入新前端依赖，不复制原型中的模拟登录和静态智能体数据。

## 后果

- 用户从开屏、登录到工作台获得一致的“联合智擎”品牌体验。
- 现有 API、权限、路由、Store 和业务状态保持不变，UI 原型不会成为第二套业务实现。
- 开屏背景包含已栅格化的宣传文案；文案变更需要 UI 重新提供图片，交互按钮和错误状态仍由 Vue 独立渲染。
- 组合 Logo 和开屏图进入 `web/public`，由 Vite 以稳定根路径提供。

## 替代方案

- 直接嵌入原型 HTML：会产生模拟登录、静态智能体与真实业务并存的问题，拒绝采用。
- 只替换 Logo：无法实现 UI 交付的开屏和登录信息层级，不能满足整体改造目标。
- 重写对话和智能体管理组件：风险大且重复现有能力；当前选择在真实组件上做最小视觉调整。

## 风险

- 开屏图为位图，在极窄或极宽比例屏幕上会出现留白；当前选择完整展示而不是裁切关键文案。
- 部署方已有自定义组织 Logo 时，工作台展开态仍显示本次交付的联合智擎组合 Logo；这是本次品牌改造的显式选择。
- 真实页面验收需要可访问的本地服务和合法账号；若认证环境不可用，必须明确记录未验证范围。
