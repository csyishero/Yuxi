# 个人 Skill 管理入口

状态：implemented
类型：feature
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

个人 Skill 已能安装、预览、申请共享和整包删除，但无法在 Skill 管理页查看完整文件树或修改自己的内容。用户为一次小改动必须在工作区手工找文件，或重新上传整包。

## 决策

在现有 Skill 详情页为个人 Skill 开放代码管理，提供文件树、文本编辑、创建与删除文件和目录、导出和整包删除。个人范围固定为本人，不复用共享 Skill 的范围和启用配置。个人 Skill 的字节由当前认证 uid 的 UserWorkspace 拥有，路由只取认证 uid，文件读写、目录遍历和删除由 no-follow 文件访问边界执行；根 SKILL.md 的 slug 必须保持与目录名一致。文本文件最多 2 MB，导出快照最多 1000 项、20 MB。此前提交的共享申请继续引用提交时快照，之后修改需要再次申请。

## 替代方案

只在预览弹窗加一个 SKILL.md 编辑框实现较快，但看不到脚本、提示词和其他依赖文件。另建一套个人 Skill 管理页会重复现有详情页。直接复用共享 Skill 的数据库配置与文件 API 会混淆存储和授权边界。

## 后果

个人 Skill 详情通过 URL 的 `scope=personal` 与同名共享 Skill 区分；后端始终以认证 uid 选择个人目录，URL 不决定权限。个人文件修改后列表元数据在重新获取卡片时更新。共享审核快照保持独立，修改个人原件不会改变此前申请内容。个人页只显示代码管理，分享范围和启用配置仍属于共享 Skill。文件可从用户工作区其他入口并发修改，管理操作因此必须继续使用 no-follow 边界。

## 验证

真实 ASGI HTTP 与临时 UserWorkspace 集成测试通过，回读文件与 ZIP，覆盖本人编辑、新建、删除、执行位保留、其他 uid 拒绝、`..` 路径、符号链接和根 SKILL.md 的标识约束。另模拟校验后删除整个 Skill、替换父目录为符号链接，确认不会重建残缺目录或删除外部文件；个人目录遍历在超过 1000 项前停止扫描。新增集成测试与相关 Workspace 单测共 16 项通过，相关 Skill unit 76 项通过，前端 lint 与生产构建通过。使用模拟数据在真实浏览器点击了个人卡片到详情页、新建、编辑、保存，并检查浅色、暗色、桌面和窄屏布局；暗色文件树颜色已修正。仓库现有三项 Web 单测失败与四项工程契约文档错误不属于本次变更。
