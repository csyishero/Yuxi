# 技能市场下架与范围治理

状态：implemented
类型：feature
Owner：backend/package/yuxi/services/skill_market_governance_service.py

## 问题

仅凭最新审核版本判断市场条目可用，无法在保留审核和安装历史的同时下架内容或调整当前市场范围。范围外成员及持有旧安装的成员可能在新 Agent 任务中继续获得不再授权的技能文件。

## 决策

市场条目分别记录上架状态、上架批次、本批次起始版本和单调修订号；安装记录用户确认的批次，申请记录提交快照时的批次。下架使批次前进并驳回此前待审申请。再次上架要求作者提交新快照、管理员审核并生成递增的不可变版本；旧安装须由本人明确升级后才确认新批次。范围调整只改变当前可见策略和修订号，不改变批次、安装指针或历史申请的审核范围。稳定条目、slug、发布版本和安装记录始终保留。

部门管理员按条目当前范围管理本部门条目，超级管理员管理全部条目并独占范围调整。管理写入按修订号拒绝过期请求；目标范围须覆盖当前批次全部版本的依赖受众。目录、详情、安装和运行时解析按当前上架状态与范围判定；旧安装仅在条目可见、批次已确认且版本属于当前批次时进入新任务的技能集。下架或范围收窄时，服务端在持有与投影刷新相同的用户锁期间撤去受影响文件，并与策略及操作日志事务协调；撤销失败使状态变更回滚。下架不主动取消已开始的 Agent 任务。

持久字段和迁移由 `backend/package/yuxi/storage/postgres/models_business.py` 与 `backend/package/yuxi/storage_migration.py` 拥有；市场查询、发布、安装和运行时投影由 `backend/package/yuxi/agents/skills/market_repository.py`、`market.py` 及技能服务拥有；管理事务由本记录的 Owner 拥有；HTTP 契约由 `backend/server/routers/skill_market_router.py` 拥有。用户操作见 [管理 Skills](../../../agents/skills-management.md)。

## 替代方案

- 删除条目、版本或安装行会破坏审核与安装历史，并释放仍被旧配置引用的 slug。
- 改写审核申请的范围无法同时表达历史审批决定与当前市场策略。
- 下架时自动升级或删除安装会替用户改变所选版本，重新上架时也无法要求本人确认。
- 只在页面隐藏条目不会约束 HTTP、Agent 解析和已投影文件。

## 后果

范围收窄使范围外旧安装暂时不可用；范围再次覆盖成员且期间未下架时，该安装自动恢复。下架后的再次上架只开放当前批次的审核版本，旧安装和旧发布文件仍保留作历史记录。不可用安装向本人提供安全摘要和卸载入口，公共市场入口不暴露已下架或范围外条目。

文件系统与 PostgreSQL 之间没有持久的分布式事务。用户锁和可恢复的文件暂存覆盖正常失败、取消及并发刷新；进程死亡、无法恢复的文件系统故障或提交确认丢失仍是残余风险。提交后的清理失败保留不可见的暂存文件并记录错误。
