# 可编辑的知识库能力权限树

- 状态：implemented
- 日期：2026-09-18
- 类型：feature
- 负责人：`backend/package/yuxi/permissions/resource_permission.py`

## 问题

知识库已经支持 READ、EDIT、MANAGE 三档成员范围，但高级权限树只是固定模板展示，不能修改，也不会影响后端接口鉴权。管理员无法在“可以贡献内容但不可删除”等预设之外，对下载、解析、入库、成员授权等具体能力进行裁剪。

本次需要在不新增数据库字段、不破坏历史知识库授权的前提下，让权限树成为真实、可持久化、可由后端执行的能力策略。

## 决策

1. 继续使用 READ、EDIT、MANAGE 作为成员范围和权限上限，不改变现有三档授权模型。
2. 在现有 `share_config` JSON 中增加可选的 `capability_policy`：
   - `read`：浏览、搜索与问答、下载；
   - `edit`：上传、更新元数据、解析、入库；
   - `manage`：配置知识库、调整共享、管理成员、删除文档、删除知识库。
3. 每一档只保存该档新增的能力。用户的有效能力为其命中档位及以下档位能力的并集。
4. `capability_policy` 缺失时使用当前固定模板，保证历史数据行为不变，不做数据库迁移。
5. 超级管理员和知识库所属部门管理员属于系统继承管理员，始终拥有全部知识库能力，不受自定义能力树裁剪。
   普通用户可以被逐人委派为单个知识库的额外管理员，命中后获得该知识库 MANAGE 档能力，但不会因此获得知识库创建、部门管理或其他知识库权限。
   额外管理员仅允许使用“指定成员”范围；不接受全局或部门级 MANAGE 授权，历史宽范围配置在运行时不产生额外管理权限。
6. 能力策略只能包含已知能力，并且能力必须位于所属档位允许的集合内。前端和后端都执行校验，后端作为最终安全边界。
7. 高级权限树支持勾选与取消；快捷授权继续负责成员范围。两种模式共同编辑同一份 `share_config`。
8. 各知识库 HTTP 接口按具体能力鉴权。智能体知识库搜索、打开和下载工具也按搜索、浏览、下载能力执行，避免绕过 HTTP 页面限制。

## 替代方案

- 为每项能力新增关系表：查询能力强，但需要数据库迁移，并让当前基于 `share_config` 的授权出现两个持久化来源，因此不采用。
- 只在前端隐藏按钮：不能阻止直接调用 HTTP 接口或 Agent 工具绕过权限，因此不采用。
- 固定保留三档模板：实现简单，但无法满足不同知识库对下载、解析、入库和删除操作的差异化控制，因此不采用。

## 后果

### 兼容性与迁移

- 不新增表或列，策略存入现有 JSON 字段。
- 旧数据没有 `capability_policy` 时自动采用默认模板。
- 保存后仍保持 `version: 2`，现有 READ/EDIT/MANAGE 范围解析不变。
- 普通用户被列入指定成员 `manage_scope` 后可管理当前知识库；既有全局/部门 `manage_scope` 不再扩大管理面，重新保存时需改为指定成员。
- 关闭某项能力只影响对应操作，不改变成员所属档位。

### 权限矩阵

| 操作 | 默认所属档位 | 能力键 | 系统继承管理员 |
| --- | --- | --- | --- |
| 查看知识库、目录、文档内容 | READ | `view` | 始终允许 |
| 检索、问答、Agent 知识库搜索 | READ | `search` | 始终允许 |
| 下载源文件、导出 | READ | `download` | 始终允许 |
| 上传、抓取或导入文件 | EDIT | `upload` | 始终允许 |
| 目录创建、改名、移动 | EDIT | `metadata` | 始终允许 |
| 文档解析 | EDIT | `parse` | 始终允许 |
| 入库、重建索引 | EDIT | `index` | 始终允许 |
| 模型、检索、图谱和维护配置 | MANAGE | `configure` | 始终允许 |
| 调整共享范围 | MANAGE | `share` | 始终允许 |
| 修改能力树和成员授权 | MANAGE | `grant` | 始终允许 |
| 删除文档 | MANAGE | `delete-document` | 始终允许 |
| 删除知识库 | MANAGE | `delete-knowledge-base` | 始终允许 |

### 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 只改前端导致接口可绕过 | 所有受控操作在后端入口做能力校验 |
| 历史知识库保存后权限意外收缩 | 缺失策略时注入默认模板，前端初始化同样采用默认值 |
| 非法能力键或越级授权 | 后端严格白名单和档位校验，非法配置返回 400 |
| Agent 工具绕过页面权限 | 工具读取可见知识库时同步解析有效能力 |
| 管理员误锁死知识库 | 系统继承管理员固定全能力，不受策略裁剪 |

- 知识库页面、HTTP 路由、外部知识库接口和 Agent 知识库工具统一执行具体能力校验。
- 权限、路由、知识库更新、Agent 工具等 127 条相关单元测试通过；知识库统计 4 条容器集成测试通过。

- 前端权限单元测试、ESLint 与生产构建通过，本地站点可正常加载。
