# 市场技能同名安装冲突

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/skills/market.py

## 问题

市场条目可见不代表当前用户能安装。用户已有同标识的个人技能，或同标识已被共享技能占用时，安装请求会被拒绝；目录却仍显示“安装”，通用 HTTP 错误处理还把具体原因显示为“请求参数错误”。

## 决策

市场列表、详情和榜单向当前用户返回 `install_conflict`。个人同名返回 `personal`，已占用的共享标识返回 `reserved`，其余返回 `null`。后端安装入口在请求时重新校验同名约束，使旧页面不能仅凭先前的目录状态直接安装。共享占用只暴露标识冲突，不附带当前用户无权查看的技能内容。

前端目录在个人同名时打开同标识的个人技能，在共享标识占用时收起安装操作；发布者自己的原件即使市场标识被占用，仍保留“查看个人技能”。安装接口的已知静态冲突原因可以显示给用户，其他 HTTP 400 详情继续由通用边界隐藏。

## 替代方案

- 允许同标识的个人与市场技能同时安装：运行时的技能选择会产生覆盖关系，用户无法从“安装成功”判断实际使用的版本。
- 只在安装失败后提示：目录仍持续提供无法完成的操作，用户需反复触发失败才能发现原因。
- 显示占用该标识的共享技能详情：可能泄露当前用户无权查看的内容。

## 后果

冲突状态以当前账号和读取时刻计算；若状态在浏览目录后改变，安装入口仍会重新检查并返回明确错误。个人上传与市场安装之间尚无共同锁，极短的并发窗口中仍可能产生同标识记录；这需要另行建立跨两条路径的串行边界。个人技能或共享技能解除占用后，重新加载市场目录可恢复安装入口。该决定不自动删除、改名或覆盖已有技能。

## 验证

独立 PostgreSQL 的真实 HTTP 测试覆盖个人同名、共享标识占用和无冲突的目录与详情，安装入口拒绝原因、安装指针未写入，以及隐藏共享内容；后端定向单测覆盖同样的服务逻辑。前端单测覆盖卡片操作、发布者原件导航和未知 HTTP 400 详情隐藏，页面样式通过构建检查。部署后的真实页面仍需手动核对。
