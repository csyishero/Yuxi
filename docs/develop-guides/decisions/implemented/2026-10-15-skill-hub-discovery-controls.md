# 技能目录的展示层级与部门范围

本记录补充 [内部 Skill 市场](2026-10-14-internal-skill-market.md) 的发现入口、排行范围和跨部门超级管理员权限；市场的发布、安装和版本规则仍由原记录说明。

状态：implemented
类型：simplification
Owner：web/src/components/extensions/SkillMarket.vue

## 问题

统一技能页的个人空间始终占据右栏。安装和点赞排行曾位于所有技能的顶层，但系统与共享技能没有这些指标。审批后的部门技能对跨部门超级管理员不可见，审核界面的“本部门”提示也无法说明实际发布范围。提交快照的长文档预览不能在弹窗内滚动。

## 决策

个人空间可展开或收起，收起后目录使用全宽。市场分类内提供排行榜抽屉，按安装或点赞查看全公司与单部门统计。统计读取当前有效成员的安装、点赞记录，榜单仅包含当前账号可查看的已发布技能；部门管理员和普通成员只能统计本人部门，超级管理员可选择任一现有部门。市场目录、详情、安装及 Agent 技能投影允许超级管理员查看部门发布的技能，普通成员与部门管理员仍受部门限制。审批范围明确显示申请提交时固化的目标部门，已发布条目标明实际部门。提交快照弹窗限制高度，文件列表和内容各自滚动。

排行榜的统计和可见性由 `backend/package/yuxi/agents/skills/market_repository.py` 与 `market.py` 决定，HTTP 参数校验由 `backend/server/routers/skill_market_router.py` 提供。榜单使用两段路径 `/-/rankings`，避免占用合法的技能 slug `rankings`。个人空间、提示和预览布局由本记录的前端 Owner 决定。

## 替代方案

- 永久隐藏个人空间会移除个人技能和审批的快捷入口。
- 保留顶层排行会让没有安装、点赞指标的技能来源参与同一排序。
- 只在前端合并跨部门技能会绕过后端可见性边界。
- 将部门 3 的已发布技能改成全公司可见会扩大原有授权范围。

## 后果

榜单按用户当前所属部门统计；人员调整部门后，部门榜数字随之变化。超级管理员可以管理和查看各部门已发布技能，但发布范围仍为申请人部门。当前仅展示有对应安装或点赞事实的榜单条目。部门选择由后端校验，客户端参数不能让非超级管理员跨部门读取。
