# 智能体 Skill 选择方式

状态：implemented
类型：feature
Owner：web/src/components/AgentRuntimeConfigForm.vue

## 问题

智能体的 `skills` 配置用空值、空列表和非空列表表示不同的运行策略，但配置页把空值投影成当前账号所有可见项的“已选择”数量。管理员与普通成员因此看到不同的数量，容易误认为智能体保存了一份固定名单。同名 Skill 仅展示名称，也无法辨认实际选择的标识。

## 决策

配置页明确展示“动态使用全部”“固定选择”“不启用”。这三种方式分别保存 `null`、非空 slug 列表和 `[]`，继续使用既有配置契约。进入固定选择时打开空白选择框，用户确认至少一项后才把名单写入配置；取消不改变配置。固定名单和选择框同时显示名称、唯一标识和来源。`yuxi.agents.context.resolve_agent_resource_options` 在当前用户可访问的 Skill 选项中附带来源，后端仍在运行时执行最终权限过滤。

## 替代方案

把动态使用全部直接转换为当前账号可见列表会固化管理员权限视角，随后新增 Skill 也不会自动进入名单。继续复用通用多选框只修改“已选择”文案，无法让用户直接辨认停用与固定选择的差别。

## 后果

动态方式只展示当前账号可用数量，并说明其他运行者随权限变化；配置页不推算其他成员的可用数量。固定方式显示保存的总数和当前账号可用数，不可访问的既有引用在调整可见选择时继续保留。选择“不启用”显式清空整个固定名单。来源信息只用于展示，资源授权仍由后端拥有。
