# 技能方向分类

状态：implemented
类型：feature
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

技能上传时无法指定用途方向，统一技能目录只能按来源查找。个人、共享和市场技能缺少跨安装与审核流程稳定保留的分类。

## 决策

每项技能从办公工具、办公效率、办公自动化、数据处理、数据分析、财务分析、经营复盘、项目管理、法律合规、开发工具和其它中选择一个方向。本地上传在安装确认时选择；远程批次中的技能逐项选择。本地 ZIP 仍只接收一个 Skill。

个人技能的方向保存在其持久 `SKILL.md` frontmatter。共享技能的方向保存在 `skills.category`，安装文件也写入同一方向；在线编辑根级 `SKILL.md` 时同步数据库。共享申请和市场申请在提交时保存选择的方向，市场发布版本在 `market_skill_releases.category` 固化方向及对应文件。市场申请预填个人技能方向，提交人可以调整，后续修改个人原件不影响已经发布的版本。历史记录和未识别的个人 frontmatter 值按“其它”展示。

主智能体在被明确要求创建个人 Skill 时，先在当前 Project Workdir 中准备文件，再通过 `install_skill` 安装到个人目录；新建的 `SKILL.md` frontmatter 必须写明有效方向。通过 `install_skill` 安装从 Sandbox 新建的 Skill 时，须选择上述方向之一，或沿用文件中已声明的有效方向；两处都没有有效方向则返回明确提示，不把新建技能静默归为“其它”。文件与工具参数同时声明却不一致时拒绝安装；确实无法归类时可显式选择 `other` 并写入文件。Git 批量安装仍逐项读取各自的 frontmatter，不使用同一个工具参数给整批技能赋值。已存在的个人技能不自动重分类，作者可编辑其 `SKILL.md` 更正方向。

统一技能页提供横向方向筛选，并与来源和关键词筛选组合使用。市场目录在 PostgreSQL 中同时应用当前用户可见范围、方向和搜索条件，然后执行排序与分页；部门发布仍仅对该部门成员和超级管理员可见。共享安装确认与市场审批共用 slug 分配锁，避免草稿期间发布同名技能导致目录出现冲突。

## 替代方案

- 只在市场发布时选择方向：个人与共享技能仍无法在上传时分类。
- 为个人技能另建数据库分类表：需要维护 UserWorkspace 文件与数据库的双向同步。
- 自由输入或多标签：会产生同义分类和组合筛选，当前只需要一个稳定方向。
- 从名称、简介做服务端关键词猜测：容易错分，且个人、审核快照与市场版本会产生不一致的方向；由创建 Skill 的 Agent 明确选择更可核对。

## 后果

个人技能导入和导出会保留方向元数据。方向代码在前端选择项和后端校验集合中同时维护；新增方向必须同步两侧。数据库 schema 升至 v12，幂等迁移给既有共享技能、审核申请和市场发布版本补充 `other` 默认值，不重写已有个人技能文件。

Agent 创建提示、工具参数和安装前校验均补齐方向约束，不改数据库结构；原有无方向的个人 Skill 保持当前分类，只有后续编辑或重新安装才会改变。

- 真实 HTTP/PostgreSQL 集成测试覆盖市场提交、审批、版本分类、部门可见性、分类先于分页、共享草稿与市场同名竞态，以及 v11 旧行迁移到 v12 的幂等性。
- 原项目部署前已生成并验证 PostgreSQL 备份；迁移后业务 schema 为 v12，旧市场版本仍在且分类为“其它”。API readiness 和技能页面返回 200，未登录分类接口返回 401。
