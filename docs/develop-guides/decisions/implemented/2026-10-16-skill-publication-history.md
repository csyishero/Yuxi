# 技能发布与审核记录以申请为事实源

状态：implemented
类型：feature
Owner：web/src/components/extensions/PublicationRecords.vue

## 问题

从当前拥有的个人 Skill 清单推导发布历史，会把未发布的原件列为“发布记录”，并使已删除原件的审核历史失去入口。作者需要按同一个 Skill 查看直接共享和上架市场的历次申请、审核结果、范围、版本及提交快照。

## 决策

“我的技能”继续列出当前可用的 Skill；“发布与审核记录”通过本人共享申请和市场申请生成，只收录至少有一条申请的个人 Skill。前端按作者和原件 slug 合并两个渠道，分别展示最近申请状态和仍可核验的已发布版本与范围。最新申请待审或被驳回时，已发布状态与新申请结果同时显示。展开技能后，两个渠道分别列出历次提交、审核意见及审核时间，并按申请 ID 打开当次不可变文件快照。

共享摘要只描述最近一次批准生成的副本，不把该副本停用误写成整个共享渠道停用；历史明细保留每个副本自身的状态。指定成员范围在摘要显示人数，在历史明细显示实际 UID。市场历史使用审核确定的范围，不用申请人后来所属部门代替。

旧共享申请缺少可核对的副本身份时，摘要只显示“审核通过”，历史明细再说明无法核对当前共享副本；不能把数据关联缺失写成新的业务状态，也不能由同名 Skill 猜测当前启停。

个人原件清单只判断原件是否仍存在。原件已删除时，申请历史与快照仍可进入，并标注“原件已删除”；原件清单读取失败时不推断原件已删除。两个申请列表任一读取失败时显示可重试错误，不以空记录代替失败。

申请和快照仍由现有共享及市场服务与 PostgreSQL 记录拥有；`web/src/components/extensions/PublicationRecords.vue` 负责读取与展示，`publicationHistory.js` 负责按原件汇总。没有新增发布表或数据库迁移，不改写共享副本、市场版本与安装数据。共享自动可用、市场主动安装及两渠道审核权限继续独立。本决定补充[内部 Skill 市场](./2026-10-14-internal-skill-market.md)与[技能页个人首页](./2026-10-15-skill-personal-home.md)的入口行为。

## 替代方案

- 继续从当前个人 Skill 清单打开记录：未发布原件与申请历史混杂，删除原件后无法查看旧记录。
- 建立统一发布历史表并回填两渠道数据：现有申请已保存审核状态和快照，新表增加同步、迁移及历史一致性负担。
- 把两渠道合并成一个状态和版本：会掩盖共享自动可用与市场主动安装、固定安装版本的差异。

## 后果

已有共享和市场申请直接进入作者的历史视图；没有申请的个人原件只留在“我的技能”。删除原件不删除其申请快照，作者仍能预览可在线读取的提交文件。作者查看快照仍受现有后端授权与文件预览限制，不能借此下载全部附件或读取他人的申请。

本人申请接口当前不分页；历史量增长会增加一次读取和页面渲染开销。需要基于实际规模和延迟再为两个渠道设计一致的分页，避免仅对前端分组截断而隐藏历史。
