# 同源技能合并展示

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

同一个人技能可以分别发布为共享副本和市场条目。共享发布占用原 slug 后，市场条目使用带后缀的 slug；只按 slug 排除重复卡片会在统一技能目录中展示两份同源技能。作者还可以安装自己发布的市场版本，使个人原件和市场安装同时进入 Agent 的默认技能集合。

## 决策

Skill 卡片服务通过已批准共享申请的原作者、个人 slug 和发布 slug 确认来源，并校验发布记录的审核人、名称、描述与创建时间。只有对应市场条目对当前用户可见时，才标记共享副本的市场来源；管理受众筛选不使用操作员视角的关联结果。前端不按名称合并。“全部”只在对应市场卡已加载且符合当前搜索、方向条件时以市场卡作为入口，否则保留一张最新的共享卡，避免分页空洞。“共享”筛选始终保留一张共享卡；历史版本继续在管理界面维护。市场卡片会说明同源共享版本已可直接使用，作者有个人原件时说明个人版本已可用。

市场安装服务在作者仍持有个人原件时拒绝新的本人安装。已有安装事实不修改；个人空间将本人原件与历史市场安装折叠为一项，原件删除后仍可安装市场版。Agent 的授权技能列表和运行时旧 slug 映射继续保留。

Agent 未显式配置技能时，每个可确认来源默认只选一个 slug，依次优先个人原件、已安装市场版本、最新可见共享副本。自动模式的说明和聊天中的 @技能候选遵循同一选择结果。显式技能列表和预加载旧 slug 保持原意，技能依赖仍可引用旧 slug。

## 替代方案

- 按名称或内容哈希合并：同名的不同作者会误合并；共享发布重写 slug 后，发布文件哈希可能不同于申请快照。
- 删除旧共享副本或既有本人安装：会改变已配置 Agent 的 slug、审核版本和依赖。
- 只用前端已加载的市场卡判断来源：分页和部门可见性会使来源误判。来源由后端权限查询确认，前端只决定当前筛选中展示哪张代表卡。

## 后果

共享审核记录、市场安装及旧 Agent 配置继续留在原项目数据中。无法通过审核记录唯一确认来源，或共享发布记录与申请元数据不一致时，目录保守保留旧共享卡。显式配置仍可同时选择同源的历史 slug；此决定只收敛未显式配置的默认选择。来源判断额外查询当前用户可见的市场条目，不修改数据库 Schema。

## 验证

- 真实 HTTP/PostgreSQL 集成测试与既有市场集成共 3 项通过，覆盖共享先发布、市场后缀、第二个共享版本、异作者同名、跨部门不可见、作者重复安装与原件删除后安装，以及默认选择和预加载旧 slug。
- Agent context 针对文件 17 项单测及默认来源选择单测通过；前端目录、Agent 模式和 @技能相关 9 项单测、全量 ESLint 和 Vite 构建通过。
- 前端全量单测 400 项中有 2 项失败：未修改的知识库页面与旧模板断言不一致，及沙箱不允许 PDF 测试监听本地端口。后端扩展单测有一个旧用例未模拟市场查询，整文件在既有多进程投影用例中长时间无进展后中止。
- 工程契约检查仅剩四项其他既有决策记录错误；契约校验器自身 62 项测试通过。浏览器安全策略未允许自动截图，需用户在当前预览页面检查最终交互。
