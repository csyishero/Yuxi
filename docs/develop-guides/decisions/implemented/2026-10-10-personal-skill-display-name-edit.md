# 个人 Skill 修改展示名时保留稳定标识

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/agents/skills/service.py

## 问题

已有个人 Skill 的 `SKILL.md` 常只有 `name`，缺少独立 `slug`。用户在编辑器中修改 `name` 后，保存接口把新名称当成标识，并因与目录名不同而拒绝整个文件。页面只显示请求参数错误。

## 决策

编辑根 `SKILL.md` 时，若未声明 `slug` 且 `name` 与目录标识不同，服务端在 YAML frontmatter 中加入原目录标识作为 `slug`，保留用户修改的展示名及其余正文。已有显式 `slug` 必须与目录标识相同；文件格式、内容大小和工作区路径校验仍在写入前执行。其他文本文件的保存流程不变。

## 替代方案

- 禁止修改 `name` 并在页面上解释：用户仍无法通过现有编辑器修改展示名。
- 根据新 `name` 重命名目录：会改变 Skill 标识、依赖与已发布快照的引用。
- 每次保存都重新序列化整个 frontmatter：可能改写用户手工排版和注释。

## 后果

第一次修改展示名会在文件顶部增加稳定的 `slug` 字段；之后的名称修改无需再次补字段。

## 验证

隔离工作区的真实 HTTP 集成测试 6 项通过，覆盖名称修改、目录标识稳定、回读和导出，以及显式错误 `slug` 拒绝。浏览器复现被本机浏览器的管理员安全检查阻止，未用其他浏览器手段绕过。
