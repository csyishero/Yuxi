# managed 子目录按独立归属清理

状态：implemented
类型：bug-fix
Owner：backend/package/yuxi/repositories/project_repository.py

## 问题

仍保留的历史 linked 项目绑定 projects 上层时，阻挡 managed 会话子目录清理。上层可见性不能单独表示子目录归属。

## 决策

本决定调整[项目生命周期](./2026-10-08-managed-project-lifecycle.md)和[无项目会话清理](./2026-10-09-standalone-conversation-directory-deletion.md)的上层重叠判定，其余目录归属与持久任务契约继续适用。

仅在清理已验证归属的 managed 子目录时，严格上层绑定不构成永久共享阻挡，不依赖上层项目是否删除。同路径、下层绑定继续阻挡；上层仍有 Run、运行时清理或排队请求则暂时阻挡。

API 登记和 worker 最终清理都锁定上层 Project 及其 Conversation，随后检查未完成工作。普通请求持有 Conversation 锁提交，新增会话及子线程持有 Project 锁，避免清理检查后又并发接纳工作。锁保持到事务结束，worker 持锁直到文件线程结束。

## 替代方案

- 必须删除历史上层项目：阻碍保留历史项目的用户清理独立子目录。
- 忽略全部重叠和活动执行：可能删除其他绑定的文件或运行中的任务文件。

## 后果

删除子目录会同时使历史上层项目看不到该目录。用户显式勾选清理作为删除意图；默认保留文件。父目录项目的请求在文件清理期间可能短暂等待。新建项目的上层重叠检查不在本决定范围内。

## 验证

单元测试覆盖活跃或已删除上层绑定放行，同路径/下层绑定拒绝，运行、排队及运行时待清理任务拒绝。PostgreSQL 测试通过独立事务和锁等待超时确认上层 Project 与 Conversation 的正式准入锁在清理事务结束前不可取得，释放后可取得。

隔离 PostgreSQL、Redis、真实 HTTP 和正式 ARQ handler 验证活跃/已删除父项目下的项目目录与独立会话目录清理，回读确认父项目状态不变、兄弟文件字节保留。默认保留文件、项目内会话共享目录拒绝及上层运行任务拒绝同时通过。本变更不调整前端界面；用户现有会话和文件未用于写入验证。
