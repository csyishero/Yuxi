# 知识库目录同级名称约束

状态：proposed
类型：architecture
Owner：backend/package/yuxi/repositories/knowledge_file_repository.py

## 问题

目录上传和历史目录整理已使用同一知识库的事务级 advisory lock，按精确名称复用真实文件夹。手动创建、重命名及移动目录仍可能经其他写入事务产生同级重名；数据库也尚未以唯一约束保护 `kb_id`、父目录和名称的组合。已有知识库可能包含大小写或 Unicode 规范化后等价的名称，直接创建唯一索引会失败。

## 提案

先审计既有同级重名和 Unicode NFC、大小写折叠后的等价名称，形成可回读的冲突报告。产品确定文件与文件夹是否共享名称空间及大小写规则后，持久化规范化名称；建立覆盖根目录 `NULL parent_id` 的数据库唯一约束。所有目录写入路径在同一事务中验证和提交名称变更，上传与历史整理继续复用目录树锁。冲突返回明确结果，不自动改名或覆盖已有文件。

## 替代方案

- 仅依赖应用层目录树锁：现有协作写入可串行化，但未使用该锁的旧路径和直接数据库写入仍可能产生重复名称。
- 直接创建唯一索引：已有冲突可能使部署迁移失败，且大小写规则尚未确定。
- 自动给冲突名称追加序号：会改变用户可见路径和引用，不接受静默修改。

## 验收标准

| 验收主张 | 失败面 | 语义 Owner | 直接证据 / 命令 | 负向案例 | 当前结果 |
|---|---|---|---|---|---|
| 历史同级名称冲突在 schema 迁移前可审计 | 唯一索引在真实数据上直接失败 | schema 迁移与审计 | 真实 PostgreSQL 迁移测试及冲突报告回读 | 同一父目录下已有等价名称 | Not run |
| 目录写入遵守统一名称空间和归一化规则 | 手动操作和上传规则不一致 | repository 与数据库约束 | 真实 HTTP/PostgreSQL integration | 并发创建、移动、重命名到相同名称及根目录空父 ID | Not run |
| 冲突不会静默改名或覆盖 | 原引用失效或文件丢失 | repository 事务与 API | 失败后回读目录树 | Unicode 和大小写等价名称 | Not run |

## 风险

规范化规则影响已有名称及跨系统路径引用，必须在产品语义确定后迁移。数据库变更必须幂等、可在历史数据上执行，并经真实 PostgreSQL 验证。当前目录上传与历史整理的已实现范围见[实体化决策](../implemented/2026-10-12-knowledge-folder-upload.md)。
