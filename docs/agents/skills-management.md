# 管理 Skills

Skill 是一个可复用的能力包，通常包含一个 `SKILL.md`、提示词、参考资料和可选脚本。智能体先看到 Skill 的描述，再按需要读取 `SKILL.md`；Skill 声明的工具和 MCP 依赖会随激活状态加入模型请求。

## 什么时候用 Skill

把一类稳定、可复用的工作方式放进 Skill，例如文档处理、研究流程、报表生成或某个外部服务的操作规范。单次任务要求写在对话中；需要跨对话复用的规则和资料再考虑 Skill 或用户工作区文件。

## Skill 保存在哪里

| 来源 | 位置和事实 | 谁可以安装/管理 |
| --- | --- | --- |
| 内置 | 随代码发布，启动时同步索引 | 管理员可以启用/停用，不能删除或直接编辑 |
| 共享上传/远程 | Skill 持久目录 + PostgreSQL 索引 | 创建人、获授权管理者；本部门发布且仅本部门可见的 Skill 也由该部门管理员管理 |
| 内部市场 | 审核版本保存在 Skill 持久目录，条目、版本、安装和点赞保存在 PostgreSQL | 作者提交个人 Skill；管理员审核；员工主动安装和升级 |
| 个人 | 当前用户 UserWorkspace 的 `agents/skills/<slug>` | 当前用户；不创建共享 Skill 数据库记录 |

运行时路径是：

- 共享和内置 Skill：`/home/gem/skills/<slug>/`，对 Agent 只读；
- 市场 Skill：`/home/gem/skills/market-release-<版本 ID>/`，运行时按已安装版本解析，只读；
- 个人 Skill：`/home/gem/user-data/agents/skills/<slug>/`，位于当前用户的 UserWorkspace。

同一用户有个人 Skill 和共享 Skill 使用同一个 slug 时，个人版本覆盖该用户看到的共享版本。删除个人版本后，如果共享版本仍可访问，会恢复共享版本。

## 创建 Skill

标准目录至少包含根级 `SKILL.md`：

```text
my-skill/
├── SKILL.md
├── tools/       # 可选脚本
└── prompts/     # 可选提示词或参考资料
```

`SKILL.md` 使用 YAML frontmatter：

```markdown
---
name: 文档整理
slug: document-cleanup
description: 按指定结构整理文档，并保留可核对的来源。
category: office_tools
tool_dependencies: []
mcp_dependencies: []
skill_dependencies: []
---

# 文档整理

## 何时使用

说明这个 Skill 解决什么问题，以及什么时候不该使用。

## 操作步骤

写出 Agent 应遵循的步骤、限制和验收方式。
```

必填字段是 `name` 和 `description`。`slug` 可省略，省略时直接使用 `name`，因此省略 slug 时 `name` 本身也必须是小写字母、数字和单个短横线组成的值；中文或带空格的展示名称会校验失败。建议显式填写 slug，把自然语言名称和稳定标识分开。名称和 slug 最多 128 个字符。通过页面上传时，`category` 可以不写在文件中，上传确认时直接选择；Agent 创建并安装个人 Skill 时，需在文件中声明方向，或在 `install_skill` 调用中指定方向。

依赖字段含义：

| 字段 | 作用 |
| --- | --- |
| `tool_dependencies` | 需要的内置工具 |
| `mcp_dependencies` | 需要的 MCP 服务器 |
| `skill_dependencies` | 需要先提供说明的其他 Skill |

个人 Skill 只作为用户文件读取，不解析这些平台依赖；需要依赖工具、MCP 或其他 Skill 时，安装为共享 Skill。

## 安装方式

进入“扩展 → Skills”，可以选择：

1. **推荐 Skill**：从推荐列表生成安装草稿。
2. **上传**：上传 ZIP 或单个 `SKILL.md`，解析后生成草稿。
3. **远程安装**：从 GitHub 仓库、ModelScope Skill 或合集拉取一个或多个 Skill。
4. **在线编辑**：编辑已有且有管理权限的共享 Skill 文件和依赖。
5. **Agent 内安装**：主智能体先在当前 Project Workdir 中创建新 Skill，再用 `install_skill` 安装到当前用户的个人来源；子智能体不能使用该工具。从沙盒目录安装时，文件与工具参数至少一处要声明有效方向，两处都声明时必须一致；Git 批量安装仍按每个文件的方向处理。

上传和远程安装都先解析为草稿，再逐项选择技能方向、选择个人或共享位置并确认。确认前可以检查名称、说明、文件和依赖；取消草稿不会写入正式 Skill。方向会随个人 Skill 文件或共享 Skill 记录保存。

### 技能方向

“扩展 → 技能”是统一技能目录，搜索、方向标签和“来源”下拉可以组合使用。来源可选全部来源、市场发布、团队共享或系统内置；本人已安装项在右侧“我的技能”和管理抽屉中查看。方向包括办公工具、办公效率、办公自动化、数据处理、数据分析、财务分析、经营复盘、项目管理、法律合规、开发工具和其它。旧技能没有方向时显示在“其它”；选择方向后，市场列表按该方向继续分页加载。

### 远程来源限制

管理员在“设置 → 基本设置 → Skill 配置 → 远程来源白名单”中维护 `remote_skill_source_policy.allowed_hosts`。默认允许 `github.com` 和 `modelscope.cn`；主机名必须精确匹配，保存空列表会关闭远程安装。

示例来源：

```text
anthropics/skills
https://github.com/anthropics/skills
https://modelscope.cn/skills/@anthropics/pdf
https://modelscope.cn/collections/MiniMax/MiniMax-Office-skills
```

除了按仓库或合集拉取，也可以在远程安装对话框切换到“全局搜索发现”，输入关键词检索 `skills.sh` 上的开源 Skills，再选择结果批量拉取和安装。搜索在一次性 Sandbox 中执行；选中结果后的实际拉取仍经过来源白名单和安装确认流程。

GitHub 的 `owner/repo` 简写会被转换为 HTTPS 地址。远程来源会在不继承全局或用户环境变量的一次性 Sandbox 中下载和提取，系统会拒绝绝对路径和路径穿越，并限制文件数、目录深度和总大小。来源白名单限制产品允许的地址，不是网络出口防火墙。

### 内置 `html-preview`

系统启动时会同步仓库内置 Skills。`html-preview` 用于在普通 Markdown 难以清晰表达指标、对比、流程、时间线或层级关系时，指导 Agent 输出静态 `html:preview` 围栏；普通 HTML 源码仍使用 `html` 代码块。前端会把该围栏清洗后放入 sandboxed iframe 预览，不依赖额外工具。

未显式配置 Skills 的 Agent 按现有资源规则自动获得该 Skill；使用显式 Skills 允许列表的 Agent 需要选择 `html-preview`。内置 `deep-research` 已声明该依赖。

安装前仍应审查 Skill 的提示词、脚本、依赖和网络行为。不要把数据库密码、云平台密钥或 `SANDBOX_PROVISIONER_TOKEN` 放进 Skill 或 Agent 环境。

## 申请共享个人 Skill

在“扩展 → Skills”打开自己的个人 Skill，点击“申请共享”，填写申请原因并提交。原因最多 1000 字，建议说明共享用途、适用人员和使用场景。系统保存提交时的文件快照；待审期间同一个人 Skill 不能重复提交。

管理员在“共享申请”中查看本部门申请，超级管理员可以查看全部申请。申请记录显示申请人、提交时间、申请原因、审核状态和审核意见；管理员可以检查提交时的文件快照，选择共享范围后批准，或填写意见驳回。申请人也可以在自己的申请记录中查看处理结果。批准会发布独立的共享副本，之后修改个人原件不会改变已发布版本；需要更新时重新申请。

## 内部 Skill 市场

在“扩展 → 技能”的统一目录中，可以按方向、来源和关键词查找 Skill；选择“市场发布”可只看团队发布条目，并查看作者、使用范围、文件和依赖。目录按最近发布展示；点击“市场热门榜”后，可切换安装人数或点赞人数，并在“统计成员”中选择全公司或本部门，超级管理员还能选择具体部门。榜单仅列出当前账号可查看的市场 Skill，统计使用当前成员的安装和点赞记录。技能卡片上的安装人数统计当前安装该条目的用户数，点赞按用户去重；这两个数值不代表实际执行次数或累计下载事件。

作者从自己的个人 Skill 提交申请，选择技能方向并填写使用场景；方向预填个人 Skill 的设置，也可在提交时调整。系统保存提交时的不可变快照、方向和申请人部门；管理员按部门边界审核，部门管理员只能发布到申请提交时所属部门，超级管理员也可以发布到全公司。部门发布的 Skill 对该部门成员和超级管理员可见。审核时检查文件和依赖；市场版本只允许依赖已有非市场 Skill。发布后条目保留稳定 slug，下一次审核通过会产生新版本，而不会覆盖旧版本文件。

市场 Skill 只有在用户主动安装后才会进入 Agent 的可选 Skill 列表；现有共享和内置 Skill 仍按原有规则自动可用。作者自己的个人原件在未安装市场版本时就已可用，原件仍存在时不能再次安装自己的市场条目。作者发布新版不会自动改变用户的安装版本，用户在市场中手动升级。运行时路径指向启动时解析的版本目录，升级后旧版本目录仍保留给已开始的运行使用。Agent 固定选择使用稳定 slug，动态选择只看用户当前已安装的市场条目。首次安装还会拒绝当前已存在的同名 Skill。

已安装的市场版本保持审核内容只读。用户可在市场详情卸载自己的安装；卸载只移除本人的安装记录和运行时可用版本，不影响发布条目、其他用户的安装、个人原件或共享副本。个人空间中折叠展示的作者原件也提供市场安装的管理入口；失去部门可见性后，旧安装仍列在个人空间并可卸载，但市场详情不可查看。需要控制某个 Agent 是否使用该技能时，到“智能体管理”中对有编辑权限的 Agent 选择自动、固定选择或不启用；内置 Agent 的配置由管理员维护。卸载后，曾固定选用该市场 slug 的 Agent 需要重新选择技能。

右侧个人空间的“全部、私人、共享、系统”按当前账号的技能来源筛选。“私人”包含本人上传的原件与本人市场安装，市场安装会标出版本；“共享”是当前可用的共享 Skill，“系统”是内置 Skill。“全部”在本人已安装市场版本和同源共享副本同时可见时只保留一个入口。搜索会同步收窄各分类数量和当前列表。点击“管理与上传”后，管理抽屉也会列出本人的市场安装：可查看发布详情、到 Agent 中配置或卸载，但不能编辑审核快照；已失去可见性的旧安装仅显示清理所需信息和卸载入口。上传或删除个人 Skill 后，右侧列表会刷新。

同一个人原件经共享审核和市场审核分别发布时，技能目录按审核来源关联。“全部来源”在对应市场条目已加载且符合当前筛选时优先展示市场卡，否则保留一张最新共享卡；来源筛为“团队共享”时仍显示一张共享卡，历史版本继续在“管理与上传”中维护。市场条目不在当前用户可见范围时，共享副本仍按自身授权展示。个人空间将作者原件与本人已安装的市场版本合并为一项，并标注历史安装版本；原件删除后，作者可以安装市场版本。旧共享副本和既有安装保留原 slug，已显式选择这些 slug 的 Agent 继续按原配置运行。

## 依赖和加载时机

系统先根据当前用户权限和 Agent 的 `skills` 配置得到有效 Skill 集合，再展开 `skill_dependencies`。Agent 未显式配置 `skills` 时，同一可确认来源默认只选一项，依次优先个人原件、已安装市场版本、最新可见共享副本；自动模式的 @技能候选按这个结果展示。显式选定或预加载的旧 slug 保持有效。依赖链会进入 Skill 描述范围，但依赖工具和 MCP 不会因此全部立刻暴露。

市场发布可能因 slug 冲突获得后缀，例如页面名称为 `report-builder`，实际标识为 `report-builder-2`。聊天中的 `@skill:<slug>` 始终引用实际标识；候选和选中标签在名称不同于标识时同时展示两者，运行时 Skill 提示也列出实际标识和读取路径。不要仅凭页面名称判断某个 `@skill` 引用不可用。

### 普通渐进加载

1. 创建 Graph 前，模型得到有效 Skill 的名称、描述和 `SKILL.md` 路径。
2. 模型读取某个可见 Skill 的 `SKILL.md` 后，该 Skill 进入 `activated_skills`。
3. 后续模型请求加入它声明的本地工具和 MCP 工具。

模型没有读取的 Skill 依赖继续隐藏。未激活的 Skill 工具即使已注册到 ToolNode，也不能被模型调用。

### 预加载

Agent 配置可以用 `preload_skills` 指定少量需要从首轮就可用的 Skill。预加载项必须属于 `skills` 中当前用户可访问的 Skill；系统会展开其依赖闭包，读取根级 `SKILL.md`，并从首轮模型请求开放依赖。

预加载的根文件缺失或不可读时，Graph 创建会明确失败，不会静默退回渐进加载。默认值为空，适合大多数 Skill。

## 权限和选择

共享 Skill 使用 `source_type`、`share_config` 和 `enabled` 表达来源、范围和启用状态。范围使用 version 2 的 `read_scope`、`manage_scope`，可以是全局、部门或指定用户；管理范围必须包含在读取范围内。

| 用户 | 可见和使用 | 可管理 |
| --- | --- | --- |
| `superadmin` | 全部允许的共享/内置 Skill | 全部非内置 Skill，及内置 Skill 的启停 |
| `admin` | 命中读取范围且已启用的 Skill | 命中管理范围的非内置 Skill，以及归属本部门且仅本部门可见的共享 Skill；内置 Skill 可启停 |
| 普通用户 | 命中读取范围且已启用的 Skill | 自己拥有的非内置 Skill；新安装的 Skill 固定进入个人来源 |

普通用户安装的新 Skill 固定进入个人来源，不配置共享范围。管理员安装到共享来源时才会写入 PostgreSQL 索引，并可以配置部门或用户范围。前端列表和 Agent 配置只展示当前用户真正可访问的 Skill，后端仍在保存和运行时重新校验。

部门管理员继承管理权限的前提是 Skill 的发布归属明确为本部门，且当前只面向本部门；仅能查看全公司、跨部门、指定人员或其他部门发布的 Skill 不等于可以管理。继承权限也适用于已停用的本部门 Skill，可用于启停、导出或删除。仅凭这项继承权限不能修改共享范围或自行委派管理权；原创建人或明确获授权的管理者仍遵循原有规则。已审核发布的个人 Skill 共享副本的内容、文件及依赖保持审核时的只读快照。市场审核版本和个人安装不由这项权限接管。没有可靠发布归属的旧共享记录继续采用原有授权。

Agent 配置中的 Skill 选择不能扩大用户的文件、知识库或 MCP 权限。

## 运行时文件行为

共享和内置 Skill 投影对 Agent 只读，但沙盒命令仍可能执行其中的脚本。脚本如需写文件，应写入当前 Project Workdir 或 User Data，而不是 Skill 目录。个人 Skill 直接从当前用户工作区读取，不会复制到共享投影。

Skill 的选择影响 Prompt 和工具激活；共享投影按用户授权集合生成，不会因为某个 Agent 选择了 Skill 就改变 Sandbox 身份。路径穿越、符号链接和跨用户访问由文件系统边界拒绝。

## 维护建议

- slug 使用小写字母、数字和单个短横线，尽量短且能表达用途。
- `description` 先说明能力和适用场景，再写实现细节。
- 把“何时使用”“不要做什么”“产物放在哪里”和“如何验收”写进 `SKILL.md`。
- 依赖链保持短小，避免循环依赖；只有真实需要时才声明工具或 MCP 依赖。
- 脚本按不可信输入处理，不读取或输出运行环境中的秘密。
- 修改共享 Skill 的依赖、范围或文件后，用一个真实 Agent Run 验证模型可见工具和最终产物。
